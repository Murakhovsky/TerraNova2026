# Домени та межі COS

Domain у COS — це не папка для зручності. Це **власник конкретної частини бізнес-смислу**.

## Що належить домену

Домен володіє:

- своїм словником;
- сутностями та станами;
- бізнес-правилами;
- дозволеними переходами;
- командами та подіями зі своєю семантикою;
- власними даними;
- use cases, які змінюють його стан.

Наприклад, Sales може визначати життєвий цикл угоди, але не повинен напряму керувати внутрішнім станом Property.

## Що не належить домену

Домен не повинен дублювати загальні механізми:

- event delivery;
- action execution;
- queue transport;
- authorization plumbing;
- observability;
- generic AI runtime.

Якщо механізм не має бізнес-словника конкретного домену, потрібно перевірити, чи не належить він Kernel або Platform.

## Взаємодія доменів

Cross-domain взаємодія відбувається через явні контракти.

Переважні способи:

1. подія повідомляє, що факт уже стався;
2. application use case координує кілька контрактів;
3. спеціальний integration contract дозволяє запитати потрібні дані;
4. process orchestration веде довгий наскрізний процес.

Прямий доступ до чужої таблиці або внутрішнього repository руйнує межу, навіть якщо технічно працює.

## Власність даних

Для кожної таблиці або агрегату має бути зрозумілий семантичний власник.

Інший домен може отримувати копію, projection або read model, але не повинен непомітно ставати другим власником того самого стану.

## Контракт модуля (module contract)

Installable Domain описує себе через module declaration. Базовий контракт ідентифікує модуль, а додаткові capability interfaces оголошують те, що модуль реально надає: події, дії, правила, політики або інші extension points.

Це краще за один гігантський interface, де кожен модуль змушений реалізувати двадцять методів, більшість із яких повертають порожній масив. Ми вже достатньо знаємо про наслідки любові людей до універсальних коробок.

## Як додавати поведінку

Перед реалізацією визначте:

- який домен володіє новою поведінкою;
- чи змінюється його vocabulary;
- які події є фактом, а які команди є наміром;
- чи потрібна синхронна відповідь;
- хто володіє persistence;
- які cross-domain залежності з'являються;
- яким тестом доводиться межа.
