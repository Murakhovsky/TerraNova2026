# Середовище виконання COS

Runtime перетворює бізнес-рішення на контрольоване виконання.

## Контекст виконання

Кожен важливий use case має знати щонайменше:

- organization або tenant;
- identity, якщо дія виконується від імені людини;
- correlation / causation context для трасування;
- повноваження;
- idempotency context там, де операцію можна повторити.

Контекст передається явно або через затверджений runtime mechanism. Він не повинен випадково збиратися з глобального стану.

## Actions

Action описує операцію, яку система повинна виконати.

Життєвий цикл включає створення, policy gate, можливе погодження людиною, claim worker-ом, виконання, завершення або повтор.

Виконавець повинен мати змогу відрізнити нову дію від повторної спроби тієї самої дії.

## Events

Event фіксує факт, який уже відбувся.

Подія не повинна означати «будь ласка, зроби». Для наміру існує command або action.

Події використовуються для слабко зв'язаної реакції інших частин системи, audit trail та побудови projections.

## Надійна вихідна черга (durable outbox)

Коли зміна бізнес-стану та публікація події мають бути узгодженими, outbox зберігає намір доставити повідомлення в тій самій транзакційній зоні.

Worker доставляє повідомлення окремо. Повторна доставка повинна бути безпечною.

## Черги та workers

Background worker не є «другим застосунком без правил». Для нього діють ті самі tenant boundaries, policies, logging та failure semantics.

Worker повинен:

- атомарно claim-ити роботу;
- мати зрозумілий retry policy;
- не створювати дубльовані побічні ефекти;
- залишати видимий failed state;
- дозволяти операційне відновлення.

## Помилки

Runtime розрізняє щонайменше:

- бізнес-відмову;
- заборону політикою;
- тимчасову технічну помилку;
- постійну технічну помилку;
- невизначений результат зовнішньої операції.

Не всі помилки потрібно retry-ити. Безкінечна черга повторів не є resilience, це просто дуже наполеглива форма заперечення реальності.

## Перевірка

Основні runtime gates покривають:

- container і routes;
- health;
- migrations;
- current contracts;
- vertical smoke scenarios;
- tenant isolation;
- queue/outbox behavior.
