# Незалежне відновлення потокових процесів Capital Markets

Незалежний sweeper перевіряє протерміновані lease для шести **відомих односимвольних BBO-пілотів**: Binance Spot, Bybit Spot, Kraken Spot/xStocks, Binance USD-M, Bybit Linear Perpetual та Massive Stocks NBBO. Це не перевірка всіх можливих типів підписок у майбутньому.

Процес спочатку зчитує кандидатів, потім у транзакції блокує загальний source guard і рядок конкретного shard. Якщо інший worker уже подовжив або перехопив lease, подія пропускається без зміни стану. Інакше sweeper змінює власника з новим `fencing_token`, після чого відкликає довіру через наявний `StreamingTrustInvalidator`.

**Критична гарантія:** якщо інвалідація завершилася помилкою БД, sweeper зберігає своє право власності до завершення TTL. Наступний запуск повторить операцію після expiry. Сам worker також не звільняє lease, доки не підтвердить скидання довіри або втрату власності.

## Запуск оператором

Запуск вимкнений за замовчуванням, але має працювати і після відключення feature flag streaming: аварійне очищення застарілих даних не повинно залежати від активності провайдера.

```bash
COS_CM_STREAM_SWEEPER_ENABLED=1 php symfony/bin/console cos:capital-markets:market-data:stream:sweep-expired --limit=100
```

Для однієї організації:

```bash
COS_CM_STREAM_SWEEPER_ENABLED=1 php symfony/bin/console cos:capital-markets:market-data:stream:sweep-expired --organization=ORG_ID --limit=100
```

Для Docker Compose додано **окремий profile**, який не запускається разом із типовим COS. Щоб ввімкнути регулярну перевірку (раз на 60 секунд), адміністратор явно запускає:

```bash
docker compose --profile cm-stream-sweeper up -d cm-stream-sweeper
docker compose logs -f cm-stream-sweeper
```

Сервіс запускає команду з внутрішнім дозволом лише в цьому opt-in profile. Якщо інвалідація повернула помилку, процес завершується з ненульовим кодом і Docker перезапускає його. Оператору потрібно контролювати перезапуски, помилки та насичення `--limit`. Зупинити моніторинг:

```bash
docker compose --profile cm-stream-sweeper stop cm-stream-sweeper
```

Для інших середовищ підходить окремий cron або системний таймер приблизно раз на хвилину. **У production profile ще не активований автоматично.**

Відповідь містить лічильники `examined`, `invalidated`, `skipped`, `failed`. При ненульовому `failed` команда завершується помилкою. Високе значення `examined` на межі `--limit` може свідчити про затримку сканування; потрібна операційна сигналізація.

## Обмеження

Наразі інвалідація має масштаб усього source, навіть якщо пізніше з'являться кілька незалежних shard. Це безпечно проти використання застарілих котирувань, але може тимчасово погіршувати доступність інших інструментів. Розширювати allowlist на багатосимвольні потоки без per-channel trust не можна.

В Runtime CI додано MySQL-перевірку: всі відомі shard, ізоляція tenant, відмова для невідомого shard, оновлення fencing, retry після збою інвалідації та звільнення після успіху. Цей тест використовує контрольований інвалідатор; окрема перевірка реальних таблиць `MarketState` та провайдерських аварійних сценаріїв ще потрібна.

Не вмикати живу торгівлю і не переводити PR у production до завершення повного приймання.
