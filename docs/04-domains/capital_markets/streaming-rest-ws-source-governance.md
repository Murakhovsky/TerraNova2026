# Захист ринкових даних від конфлікту REST та WebSocket

До цієї зміни REST-опитувач міг оновлювати канонічний стан і статус здоров'я того самого джерела, яке вже обслуговує WebSocket worker. Це створювало ризик заміни актуального стану старішим HTTP-відгуком.

## Як працює захист

Для кожної пари організації та джерела в наявній таблиці lease створюється технічний рядок із зарезервованим `shard_key=__source_writer_gate__`. Нової SQL-міграції не потрібно.

- Перед отриманням нового streaming lease worker у транзакції блокує source guard за допомогою `SELECT ... FOR UPDATE`.
- Після HTTP-запиту REST-опитувач також блокує source guard у транзакції та перевіряє всі активні streaming lease того самого джерела.
- За наявності хоча б одного активного lease REST повертає `STREAMING_ACTIVE`, не публікує RawMarketEvent/MarketState і не змінює SourceHealth.
- Якщо активного lease немає, повний запис REST-снімка разом із SourceHealth виконується в межах тієї самої транзакції, що утримує source guard до commit.
- Незалежний sweeper Binance Spot також використовує такий самий порядок захоплення блокувань: спочатку source guard, потім shard lease.

Приклад: коли REST уже отримав котирування через HTTP, але streaming worker стартував раніше за запис у базу, REST пропустить відповідь. Якщо REST першим отримав блокування та почав транзакційний запис, worker дочекається commit, захопить lease і скине довіру до попереднього стану перед публікацією нового WebSocket snapshot.

## Обмеження й наступні перевірки

Це захист **на рівні всього джерела**, а не кожного інструмента або типу події. Для багатосимвольних підписок потрібно окремо визначити політику source/shard і не блокувати незалежні торгові канали помилково.

Всі компоненти повинні використовувати одну MySQL базу та узгоджений транзакційний менеджер. HTTP-запит **не** виконується під source lock. Відомі обмеження: потрібно перевірити конкуренцію між двома окремими MySQL-з'єднаннями, таймаути, deadlock, несправності DB та повний аварійний failover. Операції, які обходять ці два шляхи ingestion, поки не захищені цим механізмом.

Новий код не вмикає streaming автоматично та не дозволяє живу торгівлю.
