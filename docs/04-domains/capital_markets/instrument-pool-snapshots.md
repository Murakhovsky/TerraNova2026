# Збереження доказів Instrument Pool

Після перевірки відповідностей інструментів можна зберегти окремий незмінний
знімок каталогу провайдера. Для кожної організації, провайдера та майданчика
система атомарно резервує спробу сканування з інтервалом щонайменше 90 секунд.
Навіть невдала спроба споживає цей інтервал, щоб уникнути лавини звернень.

```bash
COS_CM_INSTRUMENT_POOL_SNAPSHOT_ENABLED=1 php symfony/bin/console \
  cos:capital-markets:instrument-pool:snapshot ORG BINANCE VENUE --actor-id=1 --limit=200
```

Зберігаються SHA-256 ланцюга оригінальних сторінок каталогу, час, статус джерела, кількість
спостережень і результат зіставлення з наявними venue mappings. При збої
провайдера фіксується `UNAVAILABLE`, а не помилковий `DELISTED`.
Нові символи отримують `UNMAPPED_REVIEW`, без автоматичного ототожнення
економічно різних активів.

Режим **вимкнений за замовчуванням**. Команда лише зберігає докази,
не створює інструменти, не змінює їхній статус і не активує торгівлю.
Вона призначена для довіреного оператора серверної консолі.

Для повної автоматизації Instrument Pool залишаються планувальник,
перегляд/затвердження змін, створення відповідностей, ведення
життєвого циклу та обробка корпоративних подій.

## Аналіз життєвого циклу

Повторні **повні й успішні** знімки можна аналізувати командою, яка
готує оператору заявки на перевірку, не змінюючи реєстр:

```bash
php symfony/bin/console cos:capital-markets:instrument-pool:review ORG BINANCE VENUE --observations=3
```

Після трьох послідовних підтверджень символ переходить лише в
`OPERATOR_REVIEW_REQUIRED`. Будь-який збій, зміна ідентичності або
неповний (`truncated`) каталог перериває підтвердження. Це не доказ
делістингу та не дозвіл на автоматичний імпорт чи торгівлю.

## Автоматичне опитування через штатний COS Scheduler

За замовчуванням вимкнене. Після явної активації Scheduler відправляє
повідомлення до асинхронної черги, а обробник зберігає лише докази
каталогу для організацій з увімкненим модулем Capital Markets.

```dotenv
COS_CM_INSTRUMENT_POOL_SCHEDULER_ENABLED=1
COS_CM_INSTRUMENT_POOL_SCHEDULER_INTERVAL_MINUTES=15
COS_CM_INSTRUMENT_POOL_SCHEDULER_ACTOR_ID=1
COS_CM_INSTRUMENT_POOL_SCHEDULER_TARGETS_JSON=[{"organization_id":"ORG","provider":"BINANCE","venue_id":"VENUE"}]
```

Потрібен service actor із правом `capital_markets.market_data.manage` або
`capital_markets.manage` для кожної організації. Без такого права
сканування завершується помилкою без запису доказів. Для автоматичних
`PENDING`-заявок також потрібне `capital_markets.instrument_pool.propose`.
Bybit читається з усіма сторінками курсора (до 25); циклічний, обірваний
або недоступний каталог позначається `UNAVAILABLE`, а не доказом
відсутності активів. Порівняння включає і спотові пари не лише в USD/USDT.

Максимум 25 явно налаштованих організацій та майданчиків, дублікати
відхиляються. Кожен провайдер має незалежний atomic cooldown, збої
одного джерела не припиняють інші. Scheduler не активує торгові
підписки, не імпортує нові активи і не визначає автоматично `DELISTED`.

Під час великого каталогу відомі відповідності майданчика мають пріоритет
у знімку. Якщо вони всі вмістилися до звіту, `mapped_coverage_complete=true`
дозволяє перевірити їхню історію навіть за обрізаного списку нових
символів. Якщо охоплення відповідностей неповне, життєвий цикл
залишається у `INSUFFICIENT_EVIDENCE`.
