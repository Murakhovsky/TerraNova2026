# Збереження доказів Instrument Pool

Після перевірки відповідностей інструментів можна зберегти окремий незмінний
знімок каталогу провайдера. Для кожної організації, провайдера та майданчика
система атомарно резервує спробу сканування з інтервалом щонайменше 90 секунд.
Навіть невдала спроба споживає цей інтервал, щоб уникнути лавини звернень.

```bash
COS_CM_INSTRUMENT_POOL_SNAPSHOT_ENABLED=1 php symfony/bin/console \
  cos:capital-markets:instrument-pool:snapshot ORG BINANCE VENUE --actor-id=1 --limit=200
```

Зберігаються SHA-256 оригінального каталогу, час, статус джерела, кількість
спостережень і результат зіставлення з наявними venue mappings. При збої
провайдера фіксується `UNAVAILABLE`, а не помилковий `DELISTED`.
Нові символи отримують `UNMAPPED_REVIEW`, без автоматичного ототожнення
економічно різних активів.

Режим **вимкнений за замовчуванням**. Команда лише зберігає докази,
не створює інструменти, не змінює їхній статус і не активує торгівлю.
Вона призначена для довіреного оператора серверної консолі.

Для повної автоматизації Instrument Pool залишаються планувальник,
перегляд/затвердження змін, створення відповідностей, ведення
життєвого циклу та обробка корпоративних подій.

## Аналіз життєвого циклу

Повторні **повні й успішні** знімки можна аналізувати командою, яка
готує оператору заявки на перевірку, не змінюючи реєстр:

```bash
php symfony/bin/console cos:capital-markets:instrument-pool:review ORG BINANCE VENUE --observations=3
```

Після трьох послідовних підтверджень символ переходить лише в
`OPERATOR_REVIEW_REQUIRED`. Будь-який збій, зміна ідентичності або
неповний (`truncated`) каталог перериває підтвердження. Це не доказ
делістингу та не дозвіл на автоматичний імпорт чи торгівлю.
