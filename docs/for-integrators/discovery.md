# Дослідження процесу перед впровадженням

Перед налаштуванням COS потрібно отримати **операційну картину реальної роботи**, а не лише формальний регламент.

## 1. Зафіксуйте бізнес-результат

Почніть із одного вимірюваного результату. Наприклад:

- зменшити кількість втрачених звернень;
- скоротити час від заявки до першої відповіді;
- прискорити підготовку об’єкта до публікації;
- прибрати ручне дублювання даних;
- зробити контроль етапів прозорим для керівника.

Якщо результат не можна перевірити після впровадження, задача сформульована занадто розмито.

## 2. Визначте межі процесу

Для процесу мають бути зрозумілі:

- подія запуску;
- завершений результат;
- основні етапи;
- точки прийняття рішень;
- винятки та повернення назад;
- умови зупинки або відмови.

Не намагайтеся одразу описати всю компанію. Межі потрібні саме для того, щоб роботу можна було перевірити.

## 3. Опишіть учасників

Для кожної ролі зафіксуйте:

- що людина отримує на вході;
- які рішення має право приймати;
- що передає далі;
- які строки або обмеження діють;
- хто замінює її у разі відсутності.

Назва посади сама по собі нічого не пояснює. «Менеджер відповідає за клієнта» звучить пристойно, але для системи майже так само корисно, як «робіть добре».

## 4. Зберіть критичні факти

Для кожного рішення визначте, які факти потрібні. Наприклад:

- статус клієнта;
- бюджет;
- наявність документа;
- доступність об’єкта;
- дата останнього контакту;
- сума погодження;
- результат попереднього етапу.

Для кожного факту одразу зафіксуйте його першоджерело.

## 5. Розберіть винятки

Окремо пройдіть сценарії, які зазвичай не потрапляють у красиву схему:

- даних немає;
- клієнт не відповідає;
- відповідальний відсутній;
- зовнішня система недоступна;
- запис уже існує;
- погодження відхилено;
- строк прострочено;
- рішення потрібно скасувати.

Саме винятки часто визначають реальну складність упровадження.

## 6. Визначте показники

До запуску зафіксуйте, що будете вимірювати після нього:

| Показник | Приклад |
| --- | --- |
| Швидкість | час від звернення до першої дії |
| Втрати | частка справ без наступного кроку |
| Якість | частка записів із повними даними |
| Навантаження | кількість ручних операцій на одну справу |
| Результат | частка процесів, що завершилися цільовою подією |

## 7. Підготуйте карту для реалізації

Після дослідження інтегратор має передати команді не стенограму зустрічі, а структуровану модель:

- мета;
- межі;
- учасники;
- етапи;
- дані;
- рішення;
- винятки;
- показники;
- зовнішні системи.

Наступний крок: [дані та інтеграції](./data-and-integrations.md).
