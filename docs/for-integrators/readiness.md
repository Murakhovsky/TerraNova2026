# Перевірка готовності до запуску

Впровадження не варто вважати готовим лише тому, що основний сценарій один раз пройшов від початку до кінця. Перед робочим запуском потрібно перевірити весь контур.

## Процес

- [ ] Є конкретний вимірюваний бізнес-результат.
- [ ] Визначені початок і завершення процесу.
- [ ] Описані основні етапи та переходи.
- [ ] Визначені винятки, відмови та повернення назад.
- [ ] Для кожного критичного кроку є відповідальна роль.
- [ ] Зрозуміло, що робити при простроченні.

## Дані

- [ ] Для кожного критичного факту визначене першоджерело.
- [ ] Визначено, хто має право змінювати дані.
- [ ] Є правила роботи з дублями.
- [ ] Перевірено обов’язкові поля.
- [ ] Зрозуміло, які історичні дані потрібно переносити.
- [ ] Перевірена якість перенесених даних.

## Доступ і відповідальність

- [ ] Ролі отримують лише потрібні права.
- [ ] Критичні дії мають зрозумілі обмеження.
- [ ] Погодження людиною налаштоване там, де воно потрібне.
- [ ] Є спосіб відкликати доступ.
- [ ] Чутливі дані не потрапляють у зайві журнали або зовнішні сервіси.

## Інтеграції

- [ ] Перевірена автентифікація.
- [ ] Зрозумілий напрям обміну даними.
- [ ] Обробляється недоступність зовнішньої системи.
- [ ] Повторна спроба не створює дублікати.
- [ ] Невдалі операції можна знайти й повторити.
- [ ] Є відповідальний за критичні збої.

## Автоматизація і ШІ

- [ ] Для кожної автоматизованої дії визначений рівень повноважень.
- [ ] Відомо, де потрібне підтвердження людини.
- [ ] Перевірені неправильні та неповні вхідні дані.
- [ ] Є безпечна поведінка при невпевненості ШІ.
- [ ] Є резервний ручний шлях.
- [ ] Критичні рішення залишають історію та підставу.

## Користувачі

- [ ] Основні ролі пройшли реальні сценарії.
- [ ] Люди знають, що змінилося в їхній роботі.
- [ ] Визначено, куди повідомляти про проблему.
- [ ] Є коротка інструкція для щоденної роботи.
- [ ] Відомо, хто приймає рішення про зміну процесу після запуску.

## Експлуатація

- [ ] Є контроль працездатності критичних компонентів.
- [ ] Налаштовані журнали та сповіщення про важливі збої.
- [ ] Відомо, як відновлювати систему після помилки.
- [ ] Перевірено резервне копіювання критичних даних.
- [ ] Є процедура оновлення без втрати робочого стану.

## Вимірювання результату

- [ ] Зафіксовані показники до запуску.
- [ ] Визначена дата першого порівняння.
- [ ] Є людина, відповідальна за оцінку результату.
- [ ] Зрозуміло, за яких умов пілот вважається успішним.
- [ ] Зрозуміло, що робити, якщо очікуваного ефекту немає.

## Умова запуску

Система готова до робочої експлуатації, коли команда може відповісти не тільки «основний сценарій працює», а й **«ми знаємо, що станеться, якщо щось піде не за планом».**

Після проходження цього списку технічна команда може перейти до [документації для розробників](../for-developers/).
